# M4 runtime engineering review — 2026-11-10

Authorized by the owner's 2026-11-09 revision-1 M4 approval. This is the delegated D08 engineering review, not owner functional acceptance.

The exact additive SQL is packaged at `src/agrosphere_ai/sql/m4.sql` and installed by migration 0002 after unchanged 0001. It creates AI-only source revision, conflict, generated dataset, model, evaluation and source-reference tables. Source rows retain only minimal mass/date/version/scope/clocks/fingerprint facts; no raw event, workforce subject, actor, reason or prompt. Immutable triggers reject updates/deletes even for the migration owner. Runtime grants are SELECT/INSERT on these six tables only; no schema CREATE, TEMP, cross-DB, table ownership, UPDATE/DELETE/TRUNCATE or role administration. Rebuild of live forecasts reads this journal; frozen generated evaluation records are not mutable caches. A new policy/corpus produces new records.

Before migration, verify hashed short-lived manifest, companion ownership marker, exact database DSN binding, generated project identity, database ownership comment and migration principal. Runtime independently verifies the marker and nonsuperuser/non-BYPASSRLS principal before connections. Defaults expose health only. Per-request/consumer expiry and allowlist checks apply; at most two estates/ten blocks, 1,000 revisions/block, 63 evaluation dates, 1 MiB event/request and 64 KiB assistant output. Stop on uncertain ownership. No existing configuration/database/account is inspected or altered by fixture tools.

The private collection queue is fixture-provisioned, bounded to 1,000 messages, bound only to the unchanged four collection-v2 routing keys. AI's broker principal has no topology configuration, private queue read only, and writes only the private direct diagnostic exchange. It cannot publish domain events, consume quarantine or use management APIs. Commit the minimal journal before ACK. Confirm mandatory minimal diagnostics before ACK of invalid/conflicting input; lost confirmation/storage pauses and retains unacked input for explicit restart. Consumer exceptions log no payload or connection secrets. API errors are consumed by sanitizing middleware to prevent stack traces containing user input.

JWT adapter uses fixed RS256, configured issuer/audience, required signature/exp/iat/sub, bounded JWKS from a fixed configured URL, then trusted role/estate and active canonical Estate/block validation before dataset/model/evidence access. References forward the caller token, use no redirects/environment proxies and cap response bytes/time. There is no public import/train/promotion/metrics/provider route or answer cache. All quantitative answer claims link only to constructed same-scope internal paths. Closed-intent templates replace the LLM per accepted D07; provider spend remains zero, local machine cost unmetered.
